# SLZB · 私人账户观察室

**管理员配置账户，朋友用自己的用户名和密码登录，只读查看被分配给他的资产。**

支持多个查看用户及多个 Binance 现货账户。每个用户绑定一个交易所账户；同一账户也可以分配给多个用户。用户页面只有账户总览、资产持仓和交易记录，没有 API 配置、用户管理或交易入口。

## 本地预览

需要 Node.js **24.x**。

```bash
npm ci
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。尚未配置自建账号时，演示用户名 **demo**，密码 **demo123456**。演示仅有模拟数据；创建自己的配置后默认演示账号自动停用。

## 你如何配置（管理员）

在项目目录执行：

```bash
npm run setup
```

按菜单依次操作：

1. **新增交易所账户 / API**：填写账户名称、Binance 只读 API Key / Secret、主网或 Testnet，以及可选的账户本金。也可先选模拟数据测试。
2. **新增查看用户并绑定账户**：设置朋友的用户名和密码，选择他可以查看的账户。
3. 本地首次配置后重启 `npm run dev`。朋友只需要网址、自己的用户名和密码。

继续运行同一命令可以新增其他朋友、修改 API、修改本金、改密码、重新绑定账户、停用用户或撤销其全部登录。

配置写入 `.slzb/accounts.json`，密码只保存 scrypt 哈希；API 密钥留在服务端私密配置中。首次设置会自动生成 `.env.local` 中的 `SESSION_SECRET`。这两个位置均被 Git 忽略。

**完整管理员操作说明：[docs/ADMIN.md](docs/ADMIN.md)。**

## 部署到 Vercel

1. Vercel 导入 `SiaoKiasu/SLZB`，选择 Next.js 和 Node.js 24.x。
2. 在本地管理好账户与用户后执行 `npm run config:export`。
3. 在 Vercel Environment Variables 设置：

| 变量                 | 填什么                                                     |
| -------------------- | ---------------------------------------------------------- |
| `PORTAL_CONFIG_JSON` | `.slzb/vercel-config.json` 的完整内容                      |
| `SESSION_SECRET`     | `.slzb/session-secret.txt` 的完整内容                      |
| `DATABASE_URL`       | 可选：Neon Postgres 连接字符串，用于保存净值及成交同步进度 |
| `CRON_SECRET`        | 可选：至少 32 位随机值，用于后台采集                       |

4. 点击 Redeploy。后续增加用户或修改 API 后，重新导出、更新 `PORTAL_CONFIG_JSON` 并 Redeploy；保持 `SESSION_SECRET` 不变可保留未被修改用户的登录。
5. 把部署网址及各自的用户名、密码发给朋友。**不需要把配置文件或 API 信息交给他们。**

默认函数区为 Frankfurt (`fra1`)。交易所访问仍受账户适用地区及出口 IP 限制；启用严格 IP 白名单时需要固定出口方案。项目不会绕过交易所访问限制。

## 登录状态

- 使用一年有效期的持久化 HttpOnly Cookie，活跃请求自动续期，不再每 12 小时退出。
- 刷新页面、关闭页面或重启浏览器后，只要 Cookie 仍保留即可继续查看。
- 主动退出、清除浏览器 Cookie、长期一年未访问、管理员修改密码/绑定、撤销登录或停用用户后，需要重新登录。
- 用户每次请求都重新校验当前权限。停用/撤销配置生效后，下次请求即拒绝访问。
- 同一浏览器的多个标签页会同步登录/退出状态；不同查看账号应使用各自浏览器资料或设备。

## 已实现

- 中文电脑/手机 Portal，密码登录，按用户隔离账户。
- 四项指标：总资产估值（现货 Equity）、已实现盈亏、未实现盈亏、现金（USDT）；单独展示账户本金。
- 自动发现交易对、分页回溯成交，包括当前目录中的已清仓交易对；最近 1,000 笔列表、筛选、CSV 导出及全现货钱包挂单。
- 页面可见时每 60 秒自动刷新，手动刷新，缺失/过期数据提示。
- 可选持久净值，24h / 7d / 30d / 90d 曲线。Vercel 每日 Cron 为启用的真实账户保存快照。
- 账户接口只读，没有下单、撤单、提现或转账功能。

## 盈亏口径

持仓从 Binance `/api/v3/account` 自动读取，无需填写币种。该接口不提供持仓成本或盈亏；程序从 `/api/v3/exchangeInfo` 自动发现现货交易对，再通过 `/api/v3/myTrades` 从最早可用成交分页重建移动加权成本。管理员不再填写交易对或成本 JSON。

- **Equity**：现货钱包全部余额（可用 + 冻结）的 USDT 估值；不包含合约、理财和其他钱包。
- **已实现盈亏**：卖出所得减出售部分的移动加权成本和可核算手续费，是 API 可得成交范围的估算。
- **未实现盈亏**：当前持仓市值减剩余成本。必须全部非 USDT 持仓成本可核对才给出总值。
- **现金**：仅 USDT 的可用 + 冻结余额，单独列出两部分，不把 USDC 等并入现金。
- **账户本金**：管理员登记的初始投入，可留空并显示“尚未设置”；它不等于当前 Equity，不用于倒推已实现盈亏。

首次历史同步每轮最多查询 24 页，每页 1,000 笔；优先持仓/已知成交，再扫描其余交易对。首次回溯可能需要数十分钟或更久，页面显示进度，可见页面每分钟继续同步。之后按交易 ID 增量读取，并轮转检查空交易对。不同交易对不是同一时刻的快照，页面显示最早检查时间。列表最多展示最近 1,000 笔，成本计算使用已存的全部成交。

历史未同步完时不展示推算成本及已实现盈亏。余额与成交数量不匹配（例如转入币）、非 USDT 交易或第三币手续费（例如 BNB 抵扣）会显示“待核对”，不拿当前行情代替历史价格，也不把未知成本当零。API 目录不可发现的已下架交易对、闪兑、充值/提现/内部划转及外部购买成本不在当前自动重建范围；即便首次扫描完成，也不能宣称全生命周期账本完整。旧 `costs` 不再用于计算；旧 `performance` 仅保留兼容 API 字段。

本地成交进度自动保存到私密 `.slzb/ledgers/`。**Vercel 建议配置 Neon `DATABASE_URL`**，否则进度仅保留在当前实例内，冷启动会重新回溯。净值快照也使用同一个数据库，账本不包含 API 密钥。

报价为 USDT；其他稳定币按市场价格估值。未知行情资产保留在列表、不计入小计，并暂停净值快照。24h 涨跌和净值曲线不等同于资金流调整后的收益率。

接口依据：[Binance 账户与成交文档](https://developers.binance.com/en/docs/catalog/core-trading-spot-trading/api/rest-api/account)。
